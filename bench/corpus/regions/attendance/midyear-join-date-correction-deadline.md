# Correcting a wrong join date before it locks in the first-year table

The join date entered in the system is what the joining-month table reads to set a first-year joiner's prorated entitlement. If it is wrong, every day calculated since has used the wrong base.

## The window

| Situation | Deadline |
|---|---|
| No leave request yet approved against the wrong date | Correct any time before the first request is approved |
| One or more requests already approved | Correct before 31 December of the joining year |
| After 31 December of the joining year | Balance is treated as settled; only future years are corrected |

**Fixing the join date after a leave request has already been approved against it does not retroactively recalculate the days already used.** The correction adjusts the remaining balance going forward; it does not reopen an approved request.

Get the correction filed before the year closes — after that, the wrong entitlement carries the same weight as a right one when the mid-year joiner's balance lapses into the new year's full entitlement.
