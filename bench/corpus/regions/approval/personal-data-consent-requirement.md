# Consent for personal data

Some processing needs no separate consent because it is necessary for a contract already in place — payroll, statutory filings, and the recruitment process itself run on that basis. Anything beyond that, such as a reference check or non-essential contact, needs consent recorded separately from the process it supports.

## What has to be itemised

| Purpose | Consent needed |
|---|---|
| Processing to fulfil or apply for a contract | No — necessary for the process |
| Statutory filings (tax, social insurance) | No — legal requirement |
| Sharing with a third party (reference, background checks) | Yes — separate consent |
| Marketing or non-essential contact | Yes — separate consent |
| Retention beyond the stated purpose | Yes — separate consent |

**A single signature covering "processing and any related purposes" does not satisfy this.** Consent has to be itemised so the subject can decline one purpose without withdrawing the whole application — a candidate can agree to be contacted about the role applied for while declining to be considered for others.

Withdrawn consent stops future processing but does not undo a decision already made while consent was in force; it removes the basis for what comes next, not the record of what already happened.

A consent record kept alongside the draft it supports is what a subject access request will ask to see first.
