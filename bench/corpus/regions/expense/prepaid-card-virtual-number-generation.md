# Generating a single-use virtual number

## Request it against a specific purchase
A virtual number is requested through the card system against one named vendor and one expected amount — not held in reserve for whichever purchase comes up. Generate it right before checkout, not at the start of the day.

## One charge only
The number is built to clear a single authorisation. **If the vendor bills again later — a renewal, a top-up, a second instalment — that second charge is simply declined**, not queued or retried. This looks like a vendor problem from the requester's side but is the expected behaviour of a single-use number, and finance will not treat it as a card fault.

## If the vendor splits the charge
Some vendors authorise in two steps — a small verification hold followed by the real charge. Both steps count against the same number, so this is fine. What fails is a second, unrelated transaction days or weeks later.

## Getting a new number
There is no way to reopen a used number. A new purchase from the same vendor means a new request, tied to its own amount and its own record.

Recurring vendor charges belong on the corporate card or a standing prepaid card, not behind a single-use number — see the vendor table for which route a given site takes.
