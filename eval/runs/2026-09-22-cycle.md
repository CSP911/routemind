# A cycle in the map, and why it did not bite

    clean   fingerprint 2e0e821a7d9f667b   mapcheck R1–R7 pass
    cycle   fingerprint 5f09cde305f9e388   R7 FAILS, everything else passes
    same 10 `changed` questions · same answer keys · one difference: two sentences

The second way human intervention can fail is the map being **structurally** broken while every row
in it is true. A cycle is the cleanest case of that: nothing is stale, nothing is neglected, and
there is no single sentence to correct.

## What was built

Two cross-references, each accurate, pointing at each other:

    hard-moved-overtime          (payroll)     "the rate is set in attendance — start at
                                                hard-overtime-legend-revision"
    hard-overtime-legend-revision (attendance) "this page does not decide how the premium is *paid*
                                                — for that see hard-moved-overtime in payroll"

Both are true. Payroll really does not hold the rate; attendance really does not hold the payslip
line. `mapcheck` R1–R6 pass on this corpus. Only R7 fails, and it names the loop exactly.

## Result: it cost nothing

| | clean | cycle |
|---|---|---|
| hit | 10/10 | **10/10** |
| calls per question, mean | 5.5 | **5.5** |
| the two questions routed through the cycle | 5 and 6 calls | **5 and 6 calls** |

Not a small difference — **no difference.** The two overtime questions traversed both cycle
documents and spent exactly the same number of calls as before.

## Why not

The agent's own account, from `t-overtime-07`:

> That notice pointed to `hard-overtime-legend-revision` in attendance as the authoritative version
> table, which is what answered the question directly — no need to open the three individual rate
> tables.

It went payroll → attendance, got what it came for, and stopped. **It never followed the
back-pointer, because it had no reason to.** The edge pointing home was about the payslip line, and
nothing in the question asked about the payslip line.

That is the whole mechanism, and it says what a cycle needs in order to trap a walk. Each edge here
carries a *discriminator* — "for the rate, that way" and "for how it is paid, this way". An agent
holding a question about the rate reads the first and ignores the second. The loop is only a loop on
a diagram; from inside the walk it is a signpost that has already been obeyed.

## What this establishes, and what it does not

**Established, narrowly:** a two-node cycle between differentiated, accurate cross-references is
survivable at this depth, and costs nothing measurable. The existence of a cycle in the graph is not
by itself a failure of the routing layer.

**Not established:** that cycles are harmless. The fixture was too easy, and it is better to say so
than to file a negative result as a finding about cycles in general. Three harder shapes are
untested:

1. **Undifferentiated edges.** Both sides say "for overtime, see the other". Nothing tells the agent
   which end holds its answer, and the discriminator that saved this walk is gone.
2. **A question that genuinely needs both sides.** *"What multiplier applies to my 2025 Saturday
   overtime, and which pay run does it land in?"* Neither end holds the whole answer, so arriving is
   not stopping.
3. **A longer cycle.** Two nodes are visible in one step. A cycle of four or five areas may not be
   recognisable from inside a walk that only sees one table at a time.

**R7 stays regardless.** It fired correctly, it named the loop, and it is cheap. A rule that refuses
a structure this experiment found harmless is still the right rule: the harmless case and the
harmful ones look identical in the graph, and the check runs before anyone knows which one they have
built.

## Where this leaves indicator 2

Still unmeasured, and now with one shape ruled out rather than zero. The value of this run is the
mechanism it exposed — **a cycle traps a walk only when the agent cannot tell which end answers** —
which is a sharper hypothesis than the one it started with, and the three fixtures above test it
directly.
